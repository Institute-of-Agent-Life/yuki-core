# Twenty two-device Work continuations

Replay twenty independent QQ Works in each owner with the pinned SQLite build and an offline HTTP model. Each phone supplies the original waiting Work with its answer, two cold owners resume it, and the devices download the same immutable result. Keep all six actual model calls per Work in their original order and compare the question, answer and acknowledged file result against both v4 arms. Compare the full file/caption receipt after replacing only per-run identities.

A missing final call, one corrupted caption, a new event anchor shared by two parts, or a failed Work must leave the matrix unverified. Keep each failure in the denominator. This matrix measures the equivalence of those observed effects. It supplies no cross-arm speed or billing conclusion.

Run each original arm with the isolated baseline, pinned SQLite library and `bench/legacy.py A|B --works 20`. Build the Rust owner with the locked toolchain, then run `python bench/long_work_matrix.py rust C-output` and `python bench/long_work_matrix.py compare A-output B-output C-output new-result.json`. The comparator checks raw HTTP digests and each original pytest result. It compares the actual private QQ header, sender and text as well as the later question, answer and multipart delivery. A clean Rust commit is required for a verified result.
