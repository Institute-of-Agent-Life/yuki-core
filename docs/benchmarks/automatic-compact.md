# Automatic compaction after a confirmed send

Replay the original ordinary QQ turn that crosses its compaction threshold after a confirmed send. The next model request must retain the current question and the original call and receipt. Record which public history was covered by P and which private tool results E retained. Compare the actual delivered parts with the outbound events.

In the second scenario the public planner refuses the candidate before dispatch. The private fallback must preserve uncovered public history and the successful operation. A second QQ delivery, a missing paired receipt, or adopting the refused public checkpoint is a failure. Keep each attempt's original model traffic and database evidence.

The pinned A and B copies each exercised both original v4 scenarios. Save their Chat adapter payloads, original SQL facts and operation identities with `bench/legacy.py A|B --automatic-compact` using the pinned SQLite library and separate output directories. Use `python bench/automatic_trace.py A_DIR B_DIR NEW_ORACLE.gz` to compare the two arms and freeze the common input, outcomes and source digests. The Rust case runs through the native QQ peer and a loopback Chat profile. It loads the same character file, model, output cap, reasoning effort and 96,000-token threshold.

The Rust normal case confirmed all six group posts. After the public checkpoint its third model request still contained all six original delivered texts in order. Withdrawing the third part at the next reservation held the execution before another physical request. In the refusal scenario the v4 oracle injects a public planning failure. The Rust replay first sends the same public prefix to a manual Compact, rejects its prohibited tool call, and restores the actor’s ordinary permissions. That already-rejected candidate is ineligible for a second purchase during the measured turn. Rust, A and B then agree on four measured requests: the initial short-state write, the six-part send, private Compact, and the following normal request. The last request retains the uncovered public history, private checkpoint and original send receipt. The setup request is recorded separately. The full investment comparison remains open.
