# Canonical send destinations (CORE-013)

Normal sequence: Main reads the original directory, then passes a Person or Space UUID to send. If it provides a conversation, validate that conversation against the target; the fixed V4 case deliberately supplies a different binding as well, and the conversation takes precedence. A native QQ message with no target keeps its original route. A human Main can also select an observed private QQ entry or a configured, enabled QQ group in its own directory through its original receiving Presence. Before acquiring a part, the writer rechecks the original execution, destination assignment, Person root and window. It records the qualifying inbound event with the operation's dependencies. An ACK records the original actor and the destination actually used.

Failure sequence: mismatched subject/conversation, missing observation, retired assignment, ambiguous private entries or a destination outside the Work's delegated scope yields no physical call. A change after claiming a part does not move the receipt to a new user, route or generation. No second send follows an unknown ACK. For a Host gateway, an explicit target must match its original gateway entry; absent IDs must never compare equal. An alternate group must resolve through the persisted QQ route to the original Presence. Closed, paused or rerouted groups cannot acquire another part. Cross-gateway delivery and group takeover are separate capabilities.
