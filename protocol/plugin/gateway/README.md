# Host candidate

The CORE-032 candidate contains the tested native host, Rust and Python SDK distributions, both schemas and a per-file digest manifest. The host advertises business schema revision 2 separately from handshake revision 1. Development builds use Rust SDK `1.0.0-alpha.19` and Python SDK `1.0.0a19`.

Install an executable through a `[[plugins]]` entry in the owner's private `yuki.toml`. Specify `id`, `namespace`, an absolute `program` and `args`. A gateway also needs its `platform` and the installed SELF assignment's `bot_stage`. Configure `grants` individually. `commands` lists full command paths. `[[plugins.tools]]` records the name, description, JSON Schema and visibility that the host freezes for the next activation. The `env` list selects which environment variables reach this executable.

The child reads its connection binding from `YUKI_PLUGIN_BINDING`, then initiates `initialize`. The reply contains the negotiated `method_revisions` and `host_schema_revision`. Python's `yuki_plugin_sdk.host.Calls` and Rust's `yuki_plugin_sdk::host::Calls` use that reply to pair requests. Keep reading stdin while awaiting a callback. Incoming and outgoing requests can use the same ID. Business methods and their directions are defined in `host-preview.json`.

A gateway submits platform-native identifiers and segments. Its configured namespace and SELF stage select its authority. Store an input cursor only after the durable receipt. A source's lookup key comprises the original sender, source ID, namespace-bound bot, space, topic and optional native revision. For sending, the host supplies the same source route to a pure plan and then dispatches each immutable part in order. If the connection fails after dispatch, reconcile the original part handle. The host preserves the confirmed prefix.

For an explicit `message.reply_to_event_id`, the development Host resolves the original event under the selected route's entry and receiving SELF assignment. It supplies `arguments.reply` with `event_id` and `native_id`. The planner must copy this object into the first visible part's `reply`, and subsequent parts omit it. The Host validates the complete plan before sending any part and passes the same object in the first dispatch's `arguments.reply`. Missing, changed, cross-entry or invalidated sources stop delivery. The writer rechecks the source immediately before each quoted callback crosses the dispatch boundary. A source invalidated after planning can leave the original execution held with no physical dispatch, and its original operation records remain available for diagnosis.

The development `gateway.recall` method requires its explicit grant together with `gateway.inbound` and `gateway.send`. A model selects its own public sent event. The Host resolves the original confirmed part, installed receiver and recorded route, claims that part's single recall attempt, then sends the original native ID. A successful reply hides the original delivery. A platform refusal preserves the original delivery and the failed receipt. Response loss preserves unknown. Repeated logical requests and cold restarts read the same physical recall result. Authorization and the complete original reference are checked again at the writer's dispatch boundary. The retained native receipt is settled together with the model result.

Quoted delivery uses the existing argument object. Native recall adds its own negotiated method and SDK alpha.16. Real gateway transcripts bind each development candidate to its exercised capabilities. The six-method stable base is documented with its original release evidence.

Metadata observation is instance-bound and may drop under backpressure. Forget uses the durable owner, watermark and key. Cleanup acknowledges the original obligation even when its first acknowledgement was lost. The first candidate contains no approved third-party QQ native action. A maintainer must supply the actual action and scope before that method can be included.

Run `python ci/check.py CORE-032 --out <new-directory>` to exercise the host and install both SDKs. Run `python ci/host_candidate.py --manifest <verified-manifest> --out <new-directory>` on the same clean checkout to package the tested binary. The manifest records its build profile, platform, source SHA, schema and SDK versions, verification digest and contained methods.

## Gateway activity lifecycle

The opt-in `gateway.activity` notification carries an execution lease, original route, enabled flag and 5-second expiry. A live Main turn opens the lease and the Host refreshes it every 2 seconds. The gateway sends typing only to that original Bot, chat and topic. Finishing the turn closes its lease. An expired lease stops renewal.

Notifications use the bounded process queue and have no business receipt. The writer checks the current grant, original source and active turn before flushing a renewal. Disable, forget, disconnect, queue pressure and native chat-action failure must leave message delivery and its receipt independent. Telegram closes the local lease and allows the platform status to expire.

`gateway.inbound.topic_root` 是原生話題的原根訊息 ID，獨立於既有 `topic` 與防重鍵。需要同一接納的已驗 app／tenant。舊事件缺原證據時不由重投補寫。原 send 的 `route.topic_root` 只來自原 source，派發前重驗 deployment 與來源。SDK alpha.18 為本地未發布合同。

## Native resource preparation

SDK alpha.19 adds `gateway.prepare_part` under `gateway.send`. A pure plan can return `{ "preparation": true, "kind": "image", "media": <selected-original-version> }` followed by exactly one visible part with `{ "prepared_part": 0, "kind": "image" }`. File preparation uses `kind=file`. The index addresses the earlier plan part. A preparation requires the installed gateway's original application identity and `media.open` authority. It carries no reply quote. The first visible part retains any original quote.

The Host supplies a separate operation and handle for each upload and visible delivery. The upload reads the selected bytes through `media.open` and returns `{ "state": "confirmed", "resource": { "kind": "image", "key": "native-key" } }`. Failed and unknown results stop the sequence. Missing resource data leaves the upload unknown. A confirmed upload creates an immutable receipt and the later visible dispatch receives it in `arguments.prepared`, bound to the original parent, media version, namespace, application and deployment. Before dispatch the writer rechecks that receipt, source and media authority. Only a confirmed visible delivery enters `social_outbound`. Cold restart reads original outcomes without retrying an unknown physical request.
